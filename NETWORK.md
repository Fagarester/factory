# Сеть (вкладка «Сеть» в меню-шестерёнке; создано в FNative Lab, перенесено в 0.131)

Игра по сети без чужих серверов: один телефон — хост, остальные сканируют его QR-приглашение.
Код: android/.../NetTunnel.java (туннель, протокол, крипто), NetCodes (тексты QR), NetStun, NetUpnp, NetProbe (тест сети),
NetConfig (пресеты), NetPage (вкладка), NetCamera + NetQr (ZXing core 3.5.3), NetPickActivity (выбор фото).

Как идёт игра: Factorio хоста создаёт мультиплеер на 127.0.0.1:34197; туннель хоста на каждого гостя открывает свой
loopback-сокет к игре. Factorio гостя подключается к 127.0.0.1:34200 (адрес копируется в буфер).

Список «Локальные игры»: гость раз в секунду шлёт своей игре LANBroadcastMessage (3 байта: 0x0f + порт LE) с
127.0.0.1:localPort на 127.0.0.1:34196 — хост виден в списке как 127.0.0.1:34200 (формат пойман с сервера 2.1.19).

Пути (все сразу, первый ответ выигрывает): локальная сеть, публичный IPv6, проброс UPnP, пробивка NAT (STUN-адрес).
Если хост не отвечает гостю за 3 с — гость показывает ответный QR (FNA1…), хост сканирует его и сам стучится (PUNCH).

Защита: ключ комнаты (32 байта) только в QR; HELLO/WELCOME/WAIT/PUNCH с HMAC-SHA256; данные AES-256-GCM, ключи на
каждого игрока из двух случайных nonce; окно повторов 64; неподписанные пакеты отбрасываются молча. Опции: подтверждение
хостом, PIN (6 цифр, не в QR), срок приглашения, одноразовое приглашение, лимит игроков, блокировка.

Файлы: Download/FactorioNative/net.log (журнал туннеля), net-test-*.txt (тест сети); QR — Pictures/FNative.
Тест на хосте (без телефона): javac -encoding UTF-8 ядра (Net{Config,Codes,Stun,Upnp,Tunnel,Probe}.java) + тест
tests/net-src/com/factorynative/NetTest.java (35 проверок на loopback: 2 гостя, дубли/подмена пакетов, PIN,
подтверждение, лимит, одноразовое приглашение, срок, ответный код, отключение).

Состояние (lab13, 2026-11-23): пользователь подключил гостя к хосту через IPv6 (пинг 131 мс) и играл по адресу
(lab12). lab13: хост в «Локальных играх» — на телефоне не проверено. На хосте все проверки ядра прошли, тест сети на реальной сети телефона работает (STUN, UPnP).
Не проверено: интерфейс на телефоне, камера, связь через интернет между двумя телефонами, сама игра Factorio через туннель.

HUD: «пинг N мс» (GameActivity.pingText → NetPage.hudPing): гость — до хоста, хост — по игрокам (мин–макс); lab14.
Пинг официальной сети Factorio и обычной LAN-игры — позже, в тот же pingText (просьба пользователя 2026-11-23).

Обрыв и смена сети (lab15): хост не удаляет замолчавшего игрока rejoinMinutes (10 мин): подтверждение, место и сокет к игре
остаются. Гость через 2×ping+0,5 с тишины (или сразу по ConnectivityManager-callback о смене сети) шлёт новый HELLO на
последний адрес хоста и адреса приглашения; хост узнаёт gid (подпись ключом, с которым игрок вошёл) и переключает ключи
и адрес без вопроса. Тест: tests/net-src/com/factorynative/RoamTest.java (посредник со сменой адреса и обрывом 5 с).
Не решено: если сеть сменит ХОСТ и оба за NAT, гость его не найдёт (новый адрес хоста ему не известен).

Пинг в HUD для любой сетевой игры (lab16): loader/netping.c перехватывает sendto игры; адресаты с >= 15 пакетов/с — её
пиры. Раз в секунду: PingMessage Factorio (0x00 + id16; сервер отвечает 0x01/0x21 + id; так меряет браузер серверов) —
проверено с сервером 2.1.19 и клиентом FNative в proot (1 пир, ~1 мс). Клиенты на PingMessage НЕ отвечают (проверено) —
хосту ICMP echo (datagram-сокет без прав; проверен python). Режим хоста в proot не проверен (клиент не подключился
к своему же Wi-Fi-адресу). Гость в нашей сети: туннель отдаёт PingReply пингеру, а не игре (тест PingRouteTest).
Переключатель: ⚙ → «Производительность» → «Пинг в HUD» (prefs hudPing, nativeSetGamePing).
